# Actual chat shell and store inside production Next

`next-chat.json` records four passing cases: chat/dashboard crossed with baseline/Goober-generated CSS. Next 16.4.2 runs a production webpack build and owned server, with a separate local AG-UI backend proxied through Next route handlers. This combines the real AgentInterface, ChatProvider/store, composer and production OpenUI Renderer/parser in one Next App Router route. No fake store or simplified renderer substitutes for those components.

Each initial server document contains the real shell and textarea with its component stylesheet before content. JavaScript-disabled composer colors and default theme token match after hydration. All four cases report zero console/page errors. Typing into the actual composer and pressing Enter produces observed pending/running state, a 128-character assistant prefix, and the exact completed assistant content in the real store: 713 characters for chat, 1,225 for dashboard. Dashboard output contains one actual table with ten rows and twelve bar-chart paths. Final rendered text and sampled computed component styles match across CSS arms.

Each case begins a second stream and navigates with a Next client Link to a different route. Wrapper cleanup explicitly invokes the real store's `cancelMessage`; the streaming proxy propagates cancellation and the owned backend returns to zero active streams. This validates the demonstrated integration cleanup, not automatic cancellation by an unchanged ChatProvider. It is separate from the existing twenty-minute soak and makes no extended-memory claim.

The initial shell uses the default light theme. Custom theme overrides before JavaScript remain covered by the separate Next-real fixture and its scoped SSR token helper. This combined fixture does not certify custom AgentInterface themes during SSR. Response components are client-streamed after composer interaction, rather than preloaded response SSR. History/retry and multiple completed messages are covered by the standalone full-chat suite.

The fixture uses the same universal decoder selection and shared React import prebundle technique as Next-real. Next emits critical-dependency warnings for its prebundle require helper, while execution and hydration pass. An initial infrastructure attempt on backend port 4190 failed because Node fetch forbids that port; the isolated backend uses 4191. A first observer assertion used the thread's optional pending flag, which was not sampled by effects; the final assertion observes the actual response-pending state (`isRunning` before an assistant message), matching the standalone protocol. These were prototype integration/checker adjustments; production sources and frozen Next-real/chat bundles were not changed.

`next-chat-build.json` records the separate source-input SHA-256 manifest and confirms no Goober browser runtime. CSS compilation remains a static build operation. Reproduce from the styling directory with `node scripts/prepare-next-chat.mjs && npm run build --prefix next-chat-fixture && node scripts/check-next-chat.mjs` after preparing the existing real/chat assets and isolated dependencies. The checker owns ports 4189/4191, refuses occupied ports, writes failure JSON, and stops its owned processes.
